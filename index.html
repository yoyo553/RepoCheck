GitHubとは（プログラミング未経験の方へ）

GitHubは、世界中の開発者がプログラムを公開・共有しているサイトです。無料で使える高性能なAIツールの多くは、まずGitHubで公開されます。ただし「ダウンロードボタンを押せば使える」とは限らず、リポジトリ（プロジェクト1個分のフォルダ）ごとに必要な準備が違います。このツールは、その準備の中身を日本語で説明するために作りました。

覚えておくと迷わない用語

  • リポジトリ（repository / repo）：プロジェクト1個分のフォルダ。GitHubのページ1つ＝リポジトリ1つ。
  • README.md：説明書。必ず最初に読む場所。
  • clone（クローン）：そのフォルダを丸ごと自分のパソコンにコピーすること。
  • Releases：完成品の配布ページ。ここに .dmg や .zip があれば、普通のアプリと同じ感覚で入れられます。
  • Issues：バグ報告と質問の掲示板。エラーが出たら、まずエラー文をここで検索すると同じ人が見つかります。
  • Star（スター）：お気に入りの数。多いほど利用者が多く、情報も見つけやすい目安になります。

「無料で公開されている＝何に使ってもいい」ではありません。代表的なライセンスの扱いは次の通りです。

よくあるつまずき

  • Pythonのバージョン違い：「3.10専用」なのに手元が3.13で動かない、が最頻出。READMEの指定に合わせます。
  • 仮想環境を作らずに pip install：パソコン全体のPython環境が壊れる原因。必ず venv の中で入れます。
  • GPU（NVIDIA）前提：Macでは動かない、または極端に遅いことがあります。その場合はGoogle Colabが現実的です。
  • 最終更新が古い：2〜3年放置のリポジトリは、依存ライブラリ側の変更で動かないことがよくあります。

What is GitHub? (for non-programmers)

GitHub is where developers around the world publish and share their code. Many powerful free AI tools appear there first. But “click download and it works” is not always true: each repository (one project folder) needs different preparation. This tool explains that preparation in plain language.

Words worth knowing

  • Repository (repo): one project folder. One GitHub page = one repository.
  • README.md: the manual. Always read it first.
  • clone: copy the whole folder to your computer.
  • Releases: the download page for finished builds. If it has a .dmg or .zip, you can install it like any normal app.
  • Issues: the board for bug reports and questions. When you hit an error, search its text here first — someone usually had the same problem.
  • Star: the number of bookmarks. More stars usually means more users and more help available.

Reading licenses (always check before using it for work)

“Free to download” does not mean “free to use for anything”. Common licenses work like this:

LicenseCommercial useNotes
MIT / BSD / ISC / Apache-2.0◎ YesKeep the copyright notice. Apache also requires noting your changes.
MPL-2.0 / LGPL○ YesIf you modify those files, you must publish those modifications.
GPL / AGPL△ With conditionsYou may have to publish the source of your whole program. AGPL applies even if you only run it as a web service.
CC BY-NC and other NC licenses× NoNon-commercial only. Not for paid client work.
No license× Generally noAll rights stay with the author. Ask the author before using it.

* This tool gives a rough guide. For work or anything you publish, read the LICENSE file in the repository yourself. Trained models (weight files) often have a different license from the code, so check those especially carefully.

Common stumbling blocks

  • Wrong Python version: the most common problem is a project that needs 3.10 while you have 3.13. Match the version in the README.
  • Running pip install without a virtual environment: this can break Python for your whole computer. Always install inside a venv.
  • Requires an NVIDIA GPU: it may not run on a Mac, or run extremely slowly. Google Colab is the practical option then.
  • Not updated for a long time: repositories left alone for 2–3 years often break because their libraries changed.
